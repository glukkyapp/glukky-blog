Why this instruction is reasonable
The part about “Transfer to new App User ID” is directly supported by RevenueCat docs. RevenueCat says this restore behavior is the default and is recommended even for apps that require account creation before purchase, because it helps users restore when they reinstall or lose access to the original account.

The part about making sure RC is logged into the correct user before restore is also consistent with RevenueCat’s customer identity model, where custom App User IDs are what tie purchases to the right account.

One small wording fix
I would slightly soften this line:

“On bridge missing / login failed, surface a clear ‘Couldn’t reach the App Store — try again’ error”

because if login failed, that is not always an App Store reachability problem. A more accurate message would be:

“We couldn’t verify your account for restore. Please try again.”

If you want to distinguish cases:

bridge missing / native error → “Couldn’t reach the App Store — try again.”

login mismatch / identity not ready → “We couldn’t verify your account for restore — please try again.”

That would be more truthful.
