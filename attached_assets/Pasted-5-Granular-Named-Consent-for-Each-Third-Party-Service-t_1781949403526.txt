CONSENT DATA MODEL (Backend):
- New table user_consents:
  id, user_id, service_name (text), consented (boolean), 
  consented_at (timestamp), ip_address, app_version, 
  revoked_at (nullable)
  — never UPDATE; INSERT a new row on every consent change
- POST /api/user/consent — accepts array of { service, consented } 
  decisions, inserts rows, returns confirmation
- GET /api/user/consent — returns latest consent status per service 
  for the authenticated user

CONSENT STATE (Frontend):
- Create a ConsentContext (similar pattern to existing GateContext 
  and OfflineContext) in client/src/contexts/consent-context.tsx
- Context provides: consentState (per-service boolean map), 
  updateConsent(service, value), isConsentLoaded (boolean)
- On app load: fetch GET /api/user/consent and populate context 
  (if user is authenticated) or default all to false (if not yet 
  authenticated/onboarded)

CONSENT GATE (Frontend):
- Add a consent step to the onboarding flow (prepend before step 1, 
  or insert as step 0) showing one toggle per service:
  
  PostHog Analytics
  "We use PostHog to collect anonymous usage data (which screens you 
  visit, which features you use). No health values or personal 
  identifiers are sent. Data may be stored outside Hong Kong."
  [Toggle — default OFF]

  Push Notifications (OneSignal)
  "We use OneSignal to send you reminders (e.g. meal logging reminders). 
  OneSignal does not receive your health data. Notification content

  [Toggle — default OFF]

  RevenueCat (Subscriptions)
  "We use RevenueCat to process subscription payments. RevenueCat

  [Toggle — default OFF] 
  [Note: if RevenueCat is required for the paywall to function,

  AI Food Recognition (Anthropic/Claude)
  "When you photograph a meal, the image is sent to Anthropic's Claude 
  AI to identify food items. Anthropic may process this image on

  [Toggle — default OFF]

  [Include OpenAI only if step 3 above confirms it is actively used]

  core features (glucose logging, HbA1c tracking, meal logging)

CONSENT ENFORCEMENT (Frontend):
- PostHog: only call initPostHog() in App.tsx if 
  consentState.posthog === true. 
  If false, posthog must never be initialised.
- OneSignal: the Natively bridge in index.html loads unconditionally 
  as a script — that cannot be changed. Instead, gate all server-side 
  notification sending: add a consent check in server/onesignal.ts 
  before any push is sent (check user_consents table for onesignal).
- RevenueCat: gate the paywall UI — if consentState.revenuecat === false, 
  show an explanation that consent is needed for premium features.
- Claude: the POST endpoint at server/routes.ts:2220 must check the 
  user_consents table for claude consent before processing. 
  Return 403 with message "AI processing consent not given" if not 
  consented. On the frontend, if consentState.claude === false, 
  show inline message on the snap screen: 
  "Enable AI food recognition in Settings > Privacy to use this feature."
