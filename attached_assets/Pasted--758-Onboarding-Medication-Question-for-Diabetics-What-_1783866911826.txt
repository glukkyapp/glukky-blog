#758 - Onboarding: Medication Question for Diabetics
What & Why
After a user selects "Diabetes" on the health condition step (step 7), show a conditional follow-up question asking about their diabetes medications. The answer is stored for records/analytics only — it does not affect any app logic, glucose thresholds, or engine calculations.

Done looks like
Selecting "Diabetes" on step 7 leads to a new medication question screen before the consent step
Selecting "Pre-diabetes" or "General Health" skips the medication screen and goes straight to consent
Five options displayed as tiles: No medications / 1 oral medication / More than 1 oral medication / Insulin injection / Prefer not to say
Answer is saved to the user's profile in the database
The saved value is always one of the five known values — arbitrary strings are rejected by the backend
If the user goes back from the medication step and changes their health condition away from "Diabetes", any previously saved medication answer is cleared
All three locale files (en, zh-Hant, yue) contain the new strings using the translations below
The consent screen still follows as the final step regardless of the medication answer
Out of scope
Any effect on walk targets, glucose thresholds, engine calculations, or advice generation
Retroactively asking existing users (onboarding only)

Steps
Schema — Add a diabetes_medication column to the profiles table via a startup migration. Use a Postgres check constraint (or equivalent) limiting the value to exactly five strings: 'none', 'one_oral', 'multi_oral', 'insulin', 'prefer_not'. Default null (unanswered).
Backend validation — On the profile update endpoint, validate the incoming diabetesMedication value against the same five-value allowlist and return a 400 if anything else is submitted.
Back-navigation clearing — When the health condition step (step 7) is re-submitted with a value other than 'diabetes', the profile update must also set diabetesMedication to null. Enforce this server-side so a direct API call cannot leave a stale medication value on a non-diabetic profile.
Onboarding UI — Add the medication question as a new conditional step in onboarding.tsx. It must only appear when healthCondition === 'diabetes'. The VISIBLE_STEPS logic needs to handle this: if diabetes is selected, insert the medication step between step 7 and the consent screen; otherwise skip it. If the user navigates back to step 7 and changes their answer, clear any local medication state. Use the same IconTileOption tile layout as step 7. Auto-advance on selection (no separate confirm button, matching existing UX).
Locale strings — Add all six new keys to en.json, zh-Hant.json, and yue.json using the translations in the table above.
