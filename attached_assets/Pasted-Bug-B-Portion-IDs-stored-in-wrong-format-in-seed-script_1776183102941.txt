Bug B — Portion IDs stored in wrong format in seed script
File: scripts/seed-food-db.ts

Plain language
The LabelRow interface stores portionEn as "Small", "Medium", "Large" (capitalised display labels). But defaultPortionId in food_labels is meant to hold normalised internal IDs like "small", "medium", "large". When the advice endpoint resolves the user's portion and compares with eq(foodLabels.defaultPortionId, portionId), the check "Small" !== "small" fails — so no seeded food ever matches on portion in getFoodLabelByCombo.

The fix
typescript
// ❌ Wrong — stores "Small", "Medium", "Large"
defaultPortionId: row.portionEn,

// ✅ Correct — stores "small", "medium", "large"
defaultPortionId: toInternalId(row.portionEn),
Bug C — sql may not be imported in schema.ts
File: shared/schema.ts

Plain language
The foodLabels table uses the sql template tag for array defaults:

typescript
default(sql`'{}'::text[]`)
This requires sql to be imported from drizzle-orm in schema.ts. If it is not already there, the file fails to compile.

The fix
Confirm this line exists at the top of schema.ts:

typescript
import { sql } from "drizzle-orm";
If it is already imported (e.g. for other tables), no action needed.

useCount amendment — add useCount column to schema
While confirming imports, also ensure useCount is declared on the foodLabels table. All rows start at 0 — no seeded row gets a head start:

typescript
import { sql, integer } from "drizzle-orm"; // integer needed for useCount

export const foodLabels = pgTable("food_labels", {
  // ... existing columns ...
  useCount: integer("use_count").notNull().default(0),
  // ← all rows start at 0, seeded or Claude-generated
});
Bug D — Direct DB access in routes.ts bypasses storage layer
File: routes.ts (advice endpoint)

Plain language
The advice endpoint calls db.insert(foodLabels) directly, which is inconsistent — every other DB write goes through storage. If the storage layer ever adds logging, validation, or connection pooling, this call bypasses it entirely.

The fix
Add a method to storage instead:

typescript
// In IStorage interface:
saveFoodLabel(label: InsertFoodLabel): Promise<void>;

// In DatabaseStorage:
async saveFoodLabel(label: InsertFoodLabel): Promise<void> {
  await db.insert(foodLabels).values(label).onConflictDoNothing();
}

// In routes.ts advice endpoint — replace the direct db.insert call:
await storage.saveFoodLabel({
  internalId: newInternalId,
  foodNameEn: name,
  // ... other fields ...
  useCount: 0, // ← Claude-generated rows always start at 0
});
This also means db and foodLabels no longer need to be imported directly in routes.ts.

useCount amendment — saveFoodLabel always inserts useCount: 0
Claude-generated rows must start at useCount: 0 so they enter the ranking on equal footing with every other row. They can only rise in rank if real users confirm them via getFoodLabelByCombo.

Multi-Combo Under the Same Food Name
The design
food_labels holds one row per full combo (name + portion + sauces + toppings). A single food name can map to many rows:

internalId	foodName	portion	sauces	toppings	useCount
cha-siu-rice-md-sauce	叉燒飯	medium	char_siu_sauce	—	42
cha-siu-rice-lg-sauce	叉燒飯	large	char_siu_sauce	—	8
cha-siu-rice-md-plain	叉燒飯	medium	—	—	3
cha-siu-rice-claude-1	叉燒飯	medium	char_siu_sauce	spring_onion	0
useCount belongs to the whole row — it counts how many times users confirmed that exact combination. Not name separately, not portion separately. One row = one combo = one useCount.

Where useCount gets incremented
Only inside getFoodLabelByCombo, when all four labels match exactly. This is the confirmation step — the user has seen the defaults, optionally adjusted them, and tapped Confirm.

typescript
async getFoodLabelByCombo(
  name: string,
  portionId: string,
  sauceIds: string[],
  toppingIds: string[],
): Promise<FoodLabel | null> {
  const candidates = await db.select().from(foodLabels)
    .where(and(nameMatch, eq(foodLabels.defaultPortionId, portionId)));

  for (const row of candidates) {
    const rowSauces   = [...(row.defaultSauces   ?? [])].sort();
    const rowToppings = [...(row.defaultToppings ?? [])].sort();
    const inSauces    = [...sauceIds].sort();
    const inToppings  = [...toppingIds].sort();

    const matched =
      rowSauces.length   === inSauces.length   && rowSauces.every((s, i) => s === inSauces[i]) &&
      rowToppings.length === inToppings.length && rowToppings.every((t, i) => t === inToppings[i]);

    if (matched) {
      // ✅ Exact 4-label match confirmed — increment this row only
      await db.update(foodLabels)
        .set({ useCount: sql`${foodLabels.useCount} + 1` })
        .where(eq(foodLabels.internalId, row.internalId));

      return row;
    }
  }

  return null; // no exact match → caller will ask Claude
}
