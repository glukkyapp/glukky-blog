| Question                                      | Baseline evidence needed before building it                                                                                           | Build only if the answer is yes                                  |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Can the system observe an action?             | Users can indicate whether they tried a suggested swap/portion/activity change                                                        | You have reliable action data, not only meal photos              |
| Can the system observe repetition?            | Users log similar foods/meals on more than one occasion                                                                               | There are enough comparable events per user                      |
| Do users respond differently to advice?       | Some suggestions are attempted while others are ignored or rejected                                                                   | There is meaningful variation to learn from                      |
| Is personalisation genuinely needed?          | Users say generic advice is sometimes irrelevant, repetitive, or impractical                                                          | A tailored intervention solves a demonstrated problem            |
| Can you define a meaningful “better” outcome? | Feasibility rating, action adoption, repeat-choice improvement, optional glucose pattern, or another pre-defined measure is available | The model has a target other than maximising clicks/logs         |
| Can it operate with low burden?               | The necessary inputs can be captured in seconds                                                                                       | The innovation does not reintroduce excessive logging or testing |
