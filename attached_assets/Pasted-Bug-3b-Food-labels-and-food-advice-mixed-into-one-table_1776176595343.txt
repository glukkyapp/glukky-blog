Bug 3b — Food labels and food advice mixed into one table
Plain language: Food labels (what the food is, its defaults, its category flags) and food advice (the dietary text) serve different purposes and are searched at different times. They should live in separate tables. Mixing them means every advice search also pulls label data it does not need, and vice versa.

The two tables:

text
food_labels                     ← searched at snap time and label-fill time
├── internal_id
├── food_name_en/zh_hant/yue
├── default_portion_id
├── default_sauces[]
├── default_toppings[]
├── is_sugary_food
├── is_sugary_drink
├── is_oily
└── is_snack

food_advice_cache               ← searched only after user confirms final labels
├── combo_key
├── locale
├── advice_text
└── advice_source  ("seeded" | "claude")
The two search flows:

typescript
// SEARCH 1 — on photo snap (label endpoint)
// Claude returns food name → look up food_labels → return defaults to user

const labelData = await storage.getFoodLabelByName(name);
// Returns: default portion, sauces, toppings for display

// SEARCH 2 — on "Get Advice Now" (advice endpoint)
// User has confirmed final labels → get internal_id → build combo_key → look up advice

const labelData = await storage.getFoodLabelByName(confirmedName);
const comboKey = buildComboKey(
  labelData.internalId,   // ← use internal_id, not raw food name
  portionId,
  sortedSauceIds,
  sortedToppingIds
);
const advice = await storage.getCachedAdvice(comboKey, locale);
How Excel seeding maps to the two tables:

typescript
// Sheet 1 → food_labels
await db.insert(foodLabels).values({
  internalId: "char_siu_rice",
  foodNameEn: "Char Siu Rice",
  foodNameZhHant: "叉燒飯",
  defaultPortionId: "medium",
  defaultSauces: ["char_siu_sauce"],
  isSugaryFood: false,
  isOily: true,
  // ... etc
}).onConflictDoNothing();

// Sheet 2 → food_advice_cache
await db.insert(foodAdviceCache).values({
  comboKey: "char_siu_rice",  // base key for default combo
  locale: "en",
  adviceText: "🩸 Blood sugar impact: High\n...",
  adviceSource: "seeded",
}).onConflictDoNothing();
When a new unknown food appears — same split applies:

typescript
// New food identified by Claude → save labels
await db.insert(foodLabels).values({ internalId, foodNameEn, ... });

// New advice generated by Claude → save advice separately
await db.insert(foodAdviceCache).values({ comboKey, locale, adviceText, adviceSource: "claude" });
The two tables grow independently. food_labels grows when new foods are encountered. food_advice_cache grows when new combos get advice generated for the first time.
