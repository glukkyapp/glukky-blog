The required change is to turn the General food-frequency Category section from a sweet-only summary into a unified sweet-and-carb category summary.

Server summary
In server/food-frequency.ts:

Replace the sweet-specific sweetSubtypes output with a general category summary, such as categories.

Define the category union from both existing classification systems:

Sweet: sweet_drink, sweet_food

Carb: rice, noodles, bread, potatoes, other

While processing each meal, collect both item.sweetCategory and item.carbCategory.

Count each category once per meal with a per-meal Set.

Preserve existing named-food counting exactly as it is.

Return the new category list in FoodFrequencySummary; the existing API route can continue to return that summary unchanged.

Client card
In RecurringFoodInsights.tsx:

Replace the sweetSubtypes client type with the new general category list.

Update the Category block to render all returned categories, not only sweet categories.

Keep the existing Category heading/layout unless product copy requires a rename.

The card should show combinations such as:

飯類：6 餐 · 麵類：4 餐 · 甜味飲料：3 餐

A food can contribute to more than one distinct category in the same meal—for example, a sweet bun may count toward both sweet_food and bread—but neither category may be counted twice within that meal.
