The foodName injection is actually the most controllable risk and should be the first fix, not last. It's not just about breaking the prompt — if a food name from an untrusted source contains a prompt injection string, it could manipulate Claude's entire response. Fix this before anything else:

typescript
// Sanitize before injecting into any prompt

Two things missing from the analysis
Missing A — max_tokens: 512 is too low for trilingual JSON
The second Claude call returns a JSON object with portion, sauces, and extras in three locales simultaneously (based on how the prompt is written). At 512 tokens, a response like:

json
{
  "portion": "Medium / 中份 / 中份",
  "sauces": "Char siu sauce, hoisin sauce / 叉燒汁、海鮮醬 / 叉燒汁、海鮮醬",
  "extras": "Spring onion / 蔥 / 蔥"
}
...is fine. But a dish with 4+ sauces in all three scripts easily hits truncation. The fix is max_tokens: 800 plus the stop_reason check the agent mentioned.

Missing B — The two Claude calls should be merged into one
Currently the label endpoint makes two serial Claude calls — one to identify the food name, one to get portion/sauces/extras. Both have independent parse fragility. A single call returning all fields in one JSON block halves the failure surface and the latency. The agent's suggested fix shape treats them as separate, which keeps the two-call problem alive.
