Implement a full monthly subscription gate system for this app.

APP FLOW

The app flow is:

1. Splash screen
2. Register / login
3. Onboarding questions
4. App introduction
5. First weekly planner
6. Food snap tab
7. Show food labels/results
8. User taps "Get Advice"
9. Show paywall before diet advice appears
10. If user subscribes, unlock everything immediately
11. If user does not subscribe, lock the app except Profile

IMPORTANT CORRECTIONS

- Homepage is NOT permanently free.
- Homepage should also be locked after the user reaches the paywall and does not subscribe.
- Only Profile remains accessible when the app is locked.
- In hard mode, show the paywall immediately after onboarding questions are completed.
- Restore Purchases must remain available on the paywall and ideally also inside Profile/Settings.

FREE VS LOCKED RULES

Always free:
- Splash
- Register / login
- Onboarding questions
- App introduction
- Profile

Free only in SOFT mode:
- First weekly planner completion
- First food snap labels/results

NOT free:
- Homepage after paywall trigger
- Additional weekly planners
- Additional food snaps
- Roadmap
- Diet advice
- Insights
- Any main app tabs except Profile after lock

PAYWALL TRIGGER

SOFT MODE:
- User completes first weekly planner
- User tries food snap once
- Food labels are shown
- User taps "Get Advice"
- Show paywall BEFORE diet advice appears
- If user does not subscribe, lock homepage and all tabs except Profile

HARD MODE:
- User completes onboarding questions
- Show paywall immediately
- If user does not subscribe, lock homepage and all tabs except Profile
- Do not allow first weekly planner or food snap unless premium

OFF MODE:
- No paywall
- Everything accessible

SUBSCRIPTION MODEL

- Monthly subscription only
- RevenueCat entitlement ID: premium
- RevenueCat package: $rc_monthly
- Build Natively handles RevenueCat natively
- Replit never talks to RevenueCat directly
- Replit stores premium status in its own database for gating

REQUIRED DATABASE FIELDS

Add these fields to the user record:

- has_completed_onboarding (boolean, default false)
- has_created_first_weekly_plan (boolean, default false)
- has_tried_first_food_snap (boolean, default false)
- has_reached_paywall (boolean, default false)
- is_premium (boolean, default false)

FIELD RULES

- Set has_completed_onboarding = true after onboarding is completed
- Set has_created_first_weekly_plan = true after first weekly planner succeeds
- Set has_tried_first_food_snap = true after first food labels are shown
- Set has_reached_paywall = true when paywall is shown to a non-premium user
- Never reset these automatically
- is_premium is updated by frontend after Build Natively confirms subscription status

SERVER GATING RULES

Use a server-side gate before running premium features.

Feature keys:
- homepage
- weekly_plan_create
- food_snap_capture
- food_snap_advice
- roadmap
- diet_advice
- insights

Behavior:
- off mode: allow everything
- soft mode:
  - allow first weekly planner once
  - allow first food snap labels once
  - when user taps Get Advice and is not premium, show paywall
  - after paywall trigger, lock homepage and all tabs/features except Profile
- hard mode:
  - after onboarding is completed, immediately show paywall if not premium
  - lock homepage and all tabs/features except Profile unless subscribed

PAYWALL CONTENT

Title:
Upgrade to Glukky Premium

Message:
Subscribe monthly to unlock homepage access, unlimited weekly plans, food snaps, roadmap access, and AI nutrition advice.

Buttons:
- Subscribe Now
- Restore Purchases
- Maybe Later

If Maybe Later is tapped:
- dismiss modal
- do not continue the blocked action
- keep homepage and all other tabs locked
- allow Profile only

RESTORE PURCHASES

Restore Purchases means:
- user already bought the subscription before
- app checks Apple purchase history through Build Natively / RevenueCat
- if valid subscription exists, premium is restored without charging again

FRONTEND / BUILD NATIVELY

On app load and after purchase/restore:
- check RevenueCat customer info through Build Natively
- determine whether entitlement "premium" is active
- send premium status to backend via /api/update-premium-status

NAVIGATION LOCK RULE

If user is not premium and has_reached_paywall is true:
- lock homepage
- lock weekly planner
- lock food snap
- lock roadmap
- lock advice
- lock insights
- keep Profile open

Tapping locked tabs should reopen the paywall.
