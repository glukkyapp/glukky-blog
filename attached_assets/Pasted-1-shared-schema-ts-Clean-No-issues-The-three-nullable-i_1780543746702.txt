2. server/storage.ts — 3 bugs
Bug S1 — getGlucoseSpikeHistoryByFoodName: wrong column name

sql
AND ms.food_name = ${foodName}
Your schema stores the primary food name as dish_names (an array) or food_label, not food_name. Check your actual meal_snaps column — if it's dish_names[0] or a separate food_name text column. If the column doesn't exist the query silently returns 0 rows and Chart 3 always shows the empty state.

Bug S2 — getDailyGlucoseForMonth: upper bound is fragile

sql
AND local_date <= ${monthEnd}  -- monthEnd = "YYYY-MM-31"
Months with 28/29/30 days will still work because no rows exist for day 31, but February will miss nothing — this is safe. However if you ever add validation on the local_date column format this will silently fail. Use a proper last-day calculation like you already do in getMonthlySymptomCounts. Low severity but inconsistent.

Bug S3 — getAiOnlyFoodRanking: 30-day window missing
The query has no date filter. After 30 days, meal_snaps rows are purged, so this naturally shrinks — but during the first 30 days a user could see AI rankings for foods they ate months ago if the purge hasn't run yet. More importantly, the query runs against all historical snaps with no window, which may return stale rankings. Add:

sql
AND ms.snap_time >= NOW() - INTERVAL '30 days'
3. server/routes.ts — 4 bugs
Bug R1 — weekly-summary: dayBreakdown classification is wrong

js
if (hasHigh) high++;
else if (hasMed && !hasLow) medium++;
else if (hasLow) stable++;
A day with both low and medium meals falls through all three branches and is not counted — it disappears from total. This means mixed days are silently dropped. The correct logic matching your spec: if highCount > 0 → high, else if mediumCount > 0 → medium (regardless of low), else stable. Fix:

js
if (hasHigh) high++;
else if (hasMed) medium++;
else stable++;
Bug R2 — advice route: variable name name is undefined

js
const spikeHistory = name
  ? await storage.getGlucoseSpikeHistoryByFoodName(userId, name, 6)
  : [];
name is not declared in scope here. You need to extract the food name from the request body or the existing snap analysis. It should likely be req.body.foodName or whatever variable holds the identified dish name in that route. This will throw a ReferenceError at runtime.

Bug R3 — monthly-summary safety-net path: stableDays declared twice
In section 3d, computeMonthlyFromSnaps has:

js
let stableDays = 0, mediumDays = 0, highDays = 0;
// ... loop ...
let stableDays = 0, mediumDays = 0, highDays = 0;  // second declaration
The plan shows two separate code blocks that both declare let stableDays. This will cause a SyntaxError: Identifier 'stableDays' has already been declared. Remove the first block and keep only the dayImpact map approach.

Bug R4 — glucose-patterns endpoint: topList sort order not guaranteed

js
topList: patterns.topList.map(item => ({ ... }))
Chart 4's stat tiles assume topList[0] is the worst food and topList[topList.length - 1] is the best. But getGlucosePatterns must return the list sorted descending by avgSpike for this to hold. Confirm the storage method sorts by avgSpike DESC — if it sorts by entry count or food name, the tiles will show wrong foods.

5. DailyFoodSummaryBanner.tsx — 2 bugs
Bug B1 — tooltip uses position: absolute inside a card
The tooltip z-20 absolute div will be clipped by any parent with overflow: hidden. Most Card components set overflow: hidden for border-radius clipping. The top dots (early morning meals) will have their tooltip clipped upward. Use a portal or set overflow: visible on the card content wrapper.

Bug B2 — xPct uses new Date(snapTime) without timezone

js
const hour = new Date(snapTime).getHours()
snapTime is a UTC ISO string from the server. getHours() returns the local browser time, which is correct for a HK user — but if the server stores snapTime in UTC and a user snaps at 7pm HKT (11am UTC), new Date(snapTime).getHours() returns 11 not 19, placing the dot at 11am on the strip. You need to convert to the user's timezone first, same pattern as getYesterday().

8. food-reports.tsx — 2 bugs
Bug F1 — slot[mealType] TypeScript index error

js
const impact = slot[mealType];
mealType is "breakfast" | "lunch" | "dinner" (from MEAL_ROWS as const) but DailyGridSlot is a typed interface, not an index-accessible object. TypeScript will error: "Element implicitly has an 'any' type because expression of type 'string' can't be used to index type 'DailyGridSlot'". Fix:

js
const impact = slot[mealType as keyof DailyGridSlot] as string | null;
Bug F2 — Chart 8 symptom bar "normal" key not reliably last

js
symptoms: Record<string, number>
The rendering iterates Object.entries(symptoms). "normal" (→ "沒有症狀") is supposed to always be last and green, but Object.entries order depends on insertion order. The API returns a plain Record with no ordering guarantee. Add an explicit sort before rendering:

js
const sortedSymptoms = Object.entries(symptoms).sort(([a], [b]) =>
  a === "normal" ? 1 : b === "normal" ? -1 : 0
);
