Problem 1: yusycyn never gets a player ID stored (ROOT CAUSE)
The core issue is a timing race: your app calls /api/onesignal/register before BuildNatively's bridge has finished initializing, so the player ID is empty when sent to your backend.

Fix in client/src/App.tsx — replace your current player ID lookup with a retry loop:

javascript
async function getOneSignalPlayerIdWithRetry(maxAttempts = 5, delayMs = 2000) {
  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    let playerId = null;
    let source = "none";

    // Path 1: BuildNatively NativelyNotifications
    if (window.NativelyNotifications?.getPlayerId) {
      playerId = await window.NativelyNotifications.getPlayerId();
      source = "NativelyNotifications";
    }
    // Path 2: BuildNatively NativelyPush
    else if (window.NativelyPush?.getPlayerId) {
      playerId = await window.NativelyPush.getPlayerId();
      source = "NativelyPush";
    }
    // Path 3: global OneSignal Web SDK
    else if (window.OneSignal?.getUserId) {
      playerId = await new Promise(res => window.OneSignal.getUserId(res));
      source = "OneSignalWebSDK";
    }

    // Log every attempt (visible in browser console + sent to server)
    console.log(`[OneSignal probe] attempt=${attempt} source=${source} playerId=${playerId || "empty"}`);

    // Send probe to server regardless so you can see it in logs
    await fetch("/api/dev/onesignal-bridge-probe", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ attempt, source, hasId: !!playerId, timezone: Intl.DateTimeFormat().resolvedOptions().timeZone })
    }).catch(() => {});  // don't block on this

    if (playerId) {
      return { playerId, source };
    }

    // Wait before retrying
    await new Promise(res => setTimeout(res, delayMs));
  }
  return { playerId: null, source: "none" };
}
Then when calling register:

javascript
const { playerId, source } = await getOneSignalPlayerIdWithRetry();
if (playerId) {
  await fetch("/api/onesignal/register", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      playerId,
      source,
      timezone: Intl.DateTimeFormat().resolvedOptions().timeZone
    })
  });
}

Problem 3: Scheduled sends silently rolling to tomorrow
The scheduler runs too late in the day — by the time the server wakes, the local trigger time (e.g. 10 PM HKT) has already passed.

Fix in each scheduler — split users into "still future today" vs "already passed":

javascript
const now = new Date();

const futureUsers = [];
const pastUsers = [];

for (const user of registeredUsers) {
  const tz = user.device_timezone || "UTC";
  const localNow = new Date(now.toLocaleString("en-US", { timeZone: tz }));
  const [triggerHour, triggerMin] = [22, 0]; // 10 PM

  const triggerToday = new Date(localNow);
  triggerToday.setHours(triggerHour, triggerMin, 0, 0);

  if (localNow < triggerToday) {
    futureUsers.push(user); // send via scheduled timezone path
  } else {
    pastUsers.push(user);   // send immediately, don't roll to tomorrow
  }
}

// Log both groups
console.log(`daily_check_in: future=${futureUsers.length} past=${pastUsers.length} (immediate)`);

// Send future group via timezone scheduling
if (futureUsers.length > 0) {
  await sendOneSignal({ playerIds: futureUsers.map(u => u.onesignal_player_id),
    delivery_time_of_day: "10:00PM", delayed_option: "timezone" });
}

// Send past group immediately
if (pastUsers.length > 0) {
  await sendOneSignal({ playerIds: pastUsers.map(u => u.onesignal_player_id) });
}
Also move SCHEDULE_HOUR_UTC to 0 (midnight UTC = 8 AM HKT) so the daily pass always runs before any HK trigger time.
