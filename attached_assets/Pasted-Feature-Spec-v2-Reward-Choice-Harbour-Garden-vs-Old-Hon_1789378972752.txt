Feature Spec v2: Reward Choice — Harbour Garden vs. Old Hong Kong Photos
This version adds two things missing from v1: (1) what the photo system actually does at each progress step, mirrored against what the garden does, and (2) the fallback rule for when a user earns a coin before making a choice.
Part A — The choice mechanism (unchanged from v1)
Two stacked buttons — 我想建造我的海港花園 (top) and 我想看香港舊照片 (bottom) — appear where the garden currently renders, before any reward is visible. Tapping one hides both buttons and shows the corresponding reward for the rest of that cycle. On cycle completion, the view resets to the two buttons again, with no memory of the prior pick.
Part B — What the photo system does at each step (new)
The garden’s core behavior is: it progresses visibly as coins accumulate, not just at the very end. Whatever visual change happens to the garden at intermediate coin thresholds, the photo system needs an equivalent intermediate payoff, not a single reveal only at 60 coins. Otherwise photo mode would feel structurally worse than garden mode, which defeats the point of offering a real choice.
Unlock cadence: one photo unlocks every 5 coins earned. Given the coin economy (2 per completed action, 5 for graduating a struggle, capped at 60), that produces 12 unlock moments across a full cycle, roughly one photo every 2-3 days of normal engagement. This mirrors the garden’s “always something visibly changing” quality rather than a long wait followed by one big reveal.
Per-cycle photo set: each cycle draws from a set of 10-12 photos (matching the 12 unlock slots). The set should be thematically grouped, e.g. by decade or by district, so a cycle feels coherent rather than random.
Rotation across cycles: maintain 3-4 distinct sets (roughly 30-48 photos total) and advance to the next set each time a user selects photo mode in a new cycle, cycling back to the first set only after all sets have been shown. This is tracked per user (which set index they’re currently on), not globally, so two users don’t need to be in sync. This prevents a returning user from seeing the identical 10-12 photos every time they pick photo mode, which is the main way this reward would start feeling stale.
Display format: because photos are discrete items rather than one continuously-changing object like the garden, render them as a filling gallery/grid, empty or silhouette-style slots for un-earned photos, revealed thumbnails for earned ones, rather than trying to force a single “growing image” metaphor. Each new unlock at a 5-coin threshold should have a reveal animation with comparable weight and delight to whatever happens on the garden at its own intermediate stages, so neither path feels like the lesser option.
At full 60 / claim: the claim moment behaves identically to today for both paths, the “Claim Reward” trigger and the cap/reset logic don’t change. For photo mode specifically, claiming means the full 10-12 photo set for that cycle is now “complete” and stays viewable/saved somewhere (e.g., a permanent album or roadmap history), separate from the in-progress unlock view, so the user doesn’t lose access to photos they already earned once the cycle resets.
What’s different from garden mode, summarized: garden mode is one continuously-evolving object; photo mode is a discrete, countable collection that fills in at fixed 5-coin intervals and rotates its content set across cycles. The garden likely has no content-repetition problem since it’s procedurally the same object growing; photos do have a repetition problem, which the multi-set rotation solves.
Part C — Fallback rule when a coin is earned before a choice is made (new)
If a user earns their first coin of a new cycle while still in the pre-choice state (neither button tapped yet), don’t let that coin go to waste and don’t block progress waiting for a choice. Instead, automatically and randomly assign the cycle to either garden or photo mode at that moment, exactly as if the user had tapped one of the two buttons. The two buttons then disappear and the assigned reward begins accumulating progress from that first coin onward, same as if it had been chosen manually.
